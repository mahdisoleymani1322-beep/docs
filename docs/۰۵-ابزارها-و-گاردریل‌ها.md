## ۲. گاردریل‌ها

هر گاردریل روی یک سازوکار مستند Claude Code سوار است ([`۰۷`](۰۷-منابع-الگو.md) بخش ۴)، نه روی «لطفاً رعایت کن» در پرامپت.

| # | گاردریل | سازوکار | اگر نقض شود |
|---|---|---|---|
| G1 | هر ایجنت فقط ابزارهای لازمش را دارد | فیلد `tools` در frontmatter ایجنت | ابزار اصلاً در دسترس نیست |
| G2 | هر ایجنت فقط فایل‌های خروجی خودش را می‌نویسد | hook `PreToolUse` روی `Write\|Edit` در frontmatter همان ایجنت ← `guard.py --allow "judges/v{n}/rubric.json"` (الگو نسبت به پوشه‌ی اجرای جاری؛ `{n}` = دور فعلی؛ هر بخش مسیر جدا تطبیق می‌شود، پس `*` از پوشه رد نمی‌شود) | نوشتن رد می‌شود و دلیل و فهرست فایل‌های مجاز به ایجنت برمی‌گردد. **D0:** همین گارد از `settings.json` هم با `guard.py --by-agent` اجرا می‌شود (الگو از `--allow` frontmatter همان `agent_type`؛ منبع واحد)، چون hook frontmatter تا trust خاموش است؛ آزمون زنده: `evil.txt` رد شد |
| G3 | مشخصات در طول اجرا منجمدند | hook پروژه در `.claude/settings.json` روی `Write\|Edit` ← `guard.py --locked`: اگر `runs/.lock` هست یا ورودی hook `agent_id` دارد (فراخوانی از داخل ایجنت)، نوشتن در `guides/`، `rubrics/`، `schemas/`، `evals/golden/` رد می‌شود. مسیر با `realpath` یکسان می‌شود (`..` و symlink دور نمی‌زنند) | رد؛ عبور فقط با `STUDIO_ALLOW_LOCKED=1` توسط انسان |
| G4 | خروجی هر ایجنت معتبر است | hook `Stop` در frontmatter ایجنت (در subagent به `SubagentStop` تبدیل می‌شود) ← `validate.py --hook` | یک بار برمی‌گردد تا اصلاح شود؛ بار دوم اجرا `failed` می‌شود |
| G5 | بودجه‌ی جست‌وجو | hook `PreToolUse` روی `WebSearch\|WebFetch` در researcher ← `guard.py --budget web=6` (شمارنده‌ی هر اجرا در `runs/<id>/.budget/web` با قفل فایل؛ فراخوانی ردشده شمرده نمی‌شود) | جست‌وجوی هفتم رد می‌شود (hook researcher با ایجنت در فاز E متصل می‌شود) |
| G6 | ایجنت، ایجنت نمی‌سازد | `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` در `.claude/settings.json` | — |
| G7 | اجرای پرهزینه فقط با دستور انسان | `disable-model-invocation: true` در اسکیل `sales-doc-studio` | مدل نمی‌تواند خودش اسکیل را شروع کند |
| G8 | ایجنت اسکریپت اجرا نمی‌کند | Bash در `tools` هیچ ایجنتی نیست | — |
| G9 | هیچ ارسالی | هیچ ابزار ارسال (ایمیل، پیام، API) در سیستم نیست | — |

**تکرار محدود:** `validate.py --hook` شمارنده‌ی تلاش هر مرحله را در `runs/<id>/.retries/<مرحله>.v<n>` نگه می‌دارد.
به فیلدی از hook اتکا نمی‌کند که شاید نباشد. حداکثر یک بار برگشت، مطابق الگوی arkan (یک retry با فیدبک خطا).

## ۴. ضدتوهم

1. **نقل‌قول اجباری:** شاهد داور باید در متن پیدا شود ([`۰۳`](۰۳-سیستم-ارزیابی.md) بخش ۲).
2. **دفتر ادعا:** ادعای واقعی بدون منبع ساخته نمی‌شود؛ منبع URL باید در جست‌وجوهای واقعی باشد.
3. **پنهان‌نکردن کمبود:** هر فیلد الزامیِ خالی باید در `gaps.json` بیاید.
4. **برش کانتکست:** ایجنت فقط چیزی را می‌بیند که برای کارش لازم است؛ کمتر متن نامربوط، کمتر ترکیب اشتباه.
5. **ارتباط فقط از راه فایل:** هیچ ایجنتی از تاریخچه‌ی گفتگو «به خاطر نمی‌آورد».
6. **ورودی بیرونی داده است:** دستور داخل فایل مشتری یا صفحه‌ی وب اجرا نمی‌شود (قاعده‌ی پرامپت مادر راهنما).

## ۵. آنچه این گاردریل‌ها پوشش نمی‌دهند

| محدودیت | پیامد | جبران |
|---|---|---|
| hook نوشتن فقط `Write\|Edit` را می‌بیند، نه Bash | جلسه‌ی اصلی با Bash می‌تواند فایل قفل را عوض کند | ایجنت‌ها Bash ندارند؛ جلسه‌ی اصلی زیر نظر انسان است؛ تغییر مشخصات در گیت دیده می‌شود |
| `guard.py` برای شمارنده‌ی بودجه از `fcntl.flock` استفاده می‌کند | فقط پوسیکس (لینوکس و macOS)؛ ویندوز بدون WSL کار نمی‌کند | در README فرض محیط ذکر می‌شود |
| ورودی نامعتبر به hook ← عبور (fail-open) | Claude Code همیشه JSON معتبر می‌فرستد؛ اگر روزی نفرستد، گارد بی‌صدا خاموش می‌شود | آزمون `test_bad_input_passes_through` رفتار را قفل کرده؛ نسخه‌ی Claude Code در README ثبت می‌شود |
| hookهای frontmatter ایجنت (G2، G4، G5) فقط بعد از تأیید اعتماد پوشه‌ی پروژه (workspace trust) اجرا می‌شوند؛ پیش از آن ایجنت اجرا می‌شود ولی hookهایش بی‌صدا رد می‌شوند (مستندات رسمی Claude Code) | نبودِ گارد نوشتن و اعتبارسنجی بدون هیچ خطایی؛ در حالت `-p` هم «مورد اعتماد» حساب نمی‌شود | پیش از اولین اجرای واقعی پوشه را trust کنید؛ hookهای `settings.json` (G3) به این شرط وابسته نیستند و `validate.py` را ارکستریتور بعد از هر ایجنت صریح هم اجرا می‌کند (`evaluate.py finish`)؛ آزمون واقعی در E7 |
| hookها فرمان shell هستند | روی ویندوز بدون WSL یا Git Bash ممکن است کار نکنند | در README فرض محیط ذکر می‌شود |
| داور ممکن است نقل‌قول درست بیاورد ولی قضاوت غلط کند | نمره‌ی نادرست با ظاهر مستند | کالیبراسیون κ روی گلدن‌ست (L5) |
| تشخیص نفی در عبارت ممنوع ذهنی است | ممکن است مورد درست را رد یا غلط را قبول کند | داور رد فوری لایه‌ی دوم است |
| انتخاب مدل و سقف گام آزموده نشده‌اند | هزینه یا کیفیت دور از انتظار | بازبینی بعد از E7 با داده‌ی واقعی |
